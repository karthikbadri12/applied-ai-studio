# Planning before coding (Spec Kit: /speckit.plan · Superpowers: write-plan · BMAD: Architect)
1. The plan is a reviewable artifact with a decision trail: chosen, rejected, why.
2. Design layer-by-layer; only the layers the solution needs.
3. Prefer managed/boring over bespoke unless a non-negotiable forces otherwise.
4. Every regulated-data flow shows its control in the plan — not later.
